# Email releases

For a PR that changes a customer email, record the GitHub merge, production backend deployment/activation and website publication as separate events with UTC timestamps and revisions. Mark pending or inapplicable steps explicitly. Preview shares production services. Run send/retry acceptance with a disposable database and fake provider; reconcile natural production messages read-only. The confirmed welcome rollout is in `docs/confirmed-welcome-release.md`.

## Page layout
- Dream Arena opponent selection uses the shared AppSidebar and DashboardHeader; cinematic loading and battles remain full-screen to preserve the match experience.
- On player selection, a live Polar trial with exactly one linked tag and no recorded trial AI usage opens that player once per account (localStorage flag); otherwise the user picks.
- Subscription access is decided only by `supabase/functions/_shared/subscription-access.ts` (used by get-subscription-status and ai-access); cancellation uses Polar `cancel_at_period_end`, never DELETE, so users keep what they were promised until the period end.
- Coaching tasks are server-owned and unique per user/player; only a battle after the recommendation was seen with the exact recommended eight-card deck completes the task, preventing stale or cross-account results.
- Active trials use the same AI features and service limits as paid plans. Log completed trial generations for analytics. Automatic profile summaries and the first task’s follow-up keep their existing analytics treatment.
- Profile and battle cache freshness use independent timestamps and endpoint-specific atomic writes so concurrent refreshes cannot hide stale battle data.
- Coaching requests stream NDJSON progress and an explicit final status to keep the browser connection alive during generation; consumers must inspect the final status, not HTTP 200 alone.
- Alternative-card follow-ups replace the rationale and practice tip along with the deck and reset its seen timestamp, so obsolete coaching cannot qualify a match.
- No app-shell service worker: `public/sw.js` is a one-release kill-switch that clears the old Workbox caches; stale cached HTML kept users on old builds.
- Polar subscription end/revoke events apply only when they match the stored `polar_subscription_id` (`_shared/subscription-events.ts`), so late deliveries cannot close a newer subscription.
- Revenue counts only `paid` orders with net amount > 0; a first payment must belong to the same subscription and come after the trial ended.
- Trial emails use the shared sender and SQL eligibility gate. After an uncertain send, keep the original attempt. Replay its frozen request only for the same eligible task within 23 hours. Reconcile a changed choice or an older attempt only by the provider's exact delivery tag.
- Campaign-email consent is changed only through `set_my_marketing_consent`/sign-up trigger/unsubscribe functions (append-only events, per account+current address); every promotional send goes through `claim_marketing_delivery` in `_shared/marketing-gate.ts`, so consent, blocks, market/IYS rules and the off-by-default switch are re-checked at send time and a campaign reaches a recipient at most once.
- New campaign consent is accepted only while `marketing_collection_open()` (market + age rule) is true, separately from the sending switch; provider complaints/permanent bounces arrive via the Svix-verified `resend-webhook` and are stored only as address blocks, never as consent events, so nothing is recorded on a player's behalf.
- Market-scoped rules (collection, sending, age, IYS) use only a server-assigned account market (`marketing_account_markets`, admin-set), never IP/language/domain; unknown market gets only `global` rules and always needs IYS. A promo attempt with an unknown provider outcome is replayed only with its frozen key/body to the same address inside 23h, otherwise it stays `uncertain` and is never re-sent; campaign unsubscribe links carry the campaign key and withdraw only the address that campaign went to.
- The sign-up form sends a campaign choice only when its box was displayed (`shown: true`; a hidden box records nothing), and the Coach invite is claimed atomically inside `get_my_marketing_consent(p_claim_invite)` so only one session ever receives it; other screens read with `false`.
